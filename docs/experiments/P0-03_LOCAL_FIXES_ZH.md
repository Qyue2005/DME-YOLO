完整模型检查使用随机初始化、6 类、输入 `[2,3,128,128]`。每个模型完成 FP32 和 FP16 autocast/GradScaler 的检测损失反向及单步 SGD；保存模型与优化器后恢复，再执行一步；最后去除优化器、重载并完成空白图预测。

| 模型 | 参数总数（未融合） | 输出步幅 | FP32/AMP、恢复更新、strip 后推理 | 未获得梯度的可训练参数张量 |
| --- | --- | --- | --- | --- |
| `yolov10n.yaml`，运行时 nc=6 | 2,709,380 | 8、16、32 | 通过 | 0 |
| 原 `yolov10n_ODConv.yaml`，nc=6 | 31,794,846 | 8、16、32 | 运算流程通过 | 46：第 23 层 42 个，两个 ODConv 的闲置 BN 各 2 个 |

这里的“46”是参数张量数量，不是标量参数总数。主 YAML、缩放系数、层引用与 ODConv 内部 BN 的计算路径本轮保持原状；梯度实测确认了首次审计的结构疑点。参数规模的差距也说明，这两份原始配置目前不适合直接作为公平消融对照。

训练器检查另外自动生成 **4 张训练图、2 张验证图**，使用 n 基线运行 **1 轮、imgsz=128、batch=2、workers=0、AMP 关闭**，完成数据读取、训练循环、best/last 保存、strip 和最终验证。它验证了真实训练器与验证器的工程流程；没有 PCB 数据，未把合成图 AP 当作实验结果。

优化器恢复检查是读取保存的模型和 optimizer state 后执行一步，**不等于完成了真实数据上的长程断点续训**。正式 `resume=True` 恢复、真实数据损失与精度、640 输入训练容量仍需后续验收。

## 4 如何复查与保存结果

从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe tools/verify_environment.py --device cuda
.\.venv\Scripts\python.exe tools/test_p0_03_compat.py
.\.venv\Scripts\python.exe tools/smoke_p0_03.py --device cuda --trainer-smoke --output runs/p0-03-smoke-result.json
```

完整模型脚本会为每次执行新建 `runs/p0-03-smoke/时间戳/`，保存合成样例、checkpoint 和训练器日志。Git 只保存脚本、依赖、审计摘要与 JSON，不提交本地虚拟环境、下载缓存、合成图片或权重。

可选 C2f 修复后，已重新执行 6 项回归及两份主模型/合成训练检查。结果 JSON 中保存实际运行源文件的哈希，便于把验证证据与修改对应起来。旧审计 JSON 保留为修复前证据。
